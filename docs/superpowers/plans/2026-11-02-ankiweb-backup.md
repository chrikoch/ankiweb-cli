# AnkiWeb Backup Implementation Plan

> **For implementers:** Work through the checkboxes in order. Complete the feasibility and decision gate before committing to an implementation. Do not start implementation merely because this plan exists.

**Goal:** Create a headless, unattended command that downloads an AnkiWeb collection and all its media into a standalone modern `.colpkg` for Anki Desktop.

**Architecture:** First establish which Anki APIs and protocol operations can deliver a complete backup without prohibited operations. The user approved a small custom protocol client; determine its detailed implementation from the feasibility findings. Isolate downloads and package creation from the existing local collection, and verify the source package before publication. If atomic no-replace publication is unavailable, the approved exclusive-copy fallback may expose an incomplete final file during copying or after interruption.

**Tech stack:** Python 3.11+, Click, official Anki Python library, keyring, pytest; HTTPX and zstandard are the proposed protocol dependencies, subject to installation and platform checks in the transport task.

**Requirements:** `requirements/ankiweb-backup.md` is authoritative. Existing local `.anki2` snapshot commands remain separate.

## Phase 2: Implementation, after the gate

- [x] **Credentials reader.** Create `src/ankiweb_cli/backup_credentials.py` and `tests/test_backup_credentials.py`. Define immutable `BackupCredentials(username: str, password: str)` with a redacted representation and `load_credentials(path: Path) -> BackupCredentials`. Parse UTF-8 TOML `[ankiweb]`, require nonempty strings and a regular file, inspect the opened file's Linux group/other mode bits, and sanitize errors. Do not change existing keyring commands. First write tests for valid credentials, missing/malformed input, missing or empty keys, Linux `0600` versus group/other access, Windows/macOS behavior, and no password in exceptions or representation; run `python -m pytest tests/test_backup_credentials.py -v` and observe failure. Implement, rerun the same command and require all tests to pass.

- [x] **Download-only transport.** Create `src/ankiweb_cli/ankiweb_reader.py`, `tests/test_ankiweb_reader.py`, and reusable synthetic-server helpers in `tests/ankiweb_server_fixture.py`; update `pyproject.toml` after verifying HTTPX/zstandard version and wheel compatibility with Python 3.11–3.13 and the Pi's aarch64. Define `AnkiWebReader.login(username: str, password: str) -> None`, `collection_meta() -> CollectionMeta`, and `download_collection(destination: Path) -> None`; `CollectionMeta` holds collection mod, schema mod and USN. Use the protocol/version and headers in the feasibility probes, stream bodies, and allow only `/sync/hostKey`, `/sync/meta`, `/sync/download`, `/msync/begin`, `/msync/mediaChanges`, `/msync/downloadFiles`, and `/msync/mediaSanity`. Disable automatic redirects; validate HTTPS destination and port before forwarding secrets, bound redirects, and inject loopback trust only in tests. Test login, collection bytes, compressed/truncated/error replies, redirect success, malformed/untrusted destinations, loops, and no credentials or hkey in errors. Run `python -m pytest tests/test_ankiweb_reader.py -v` before and after implementation; the final run must pass. Use only local synthetic data and assert prohibited endpoints are rejected. Real AnkiWeb behavior stays an acceptance gate.

- [x] **Media reader.** Extend `ankiweb_reader.py` and `tests/test_ankiweb_reader.py` with `MediaChange(name: str, usn: int, sha1: str)`, `media_usn() -> int`, `media_changes(after_usn: int) -> list[MediaChange]`, `media_sanity(file_count: int) -> bool`, and `download_media(names: list[str], destination: Path) -> set[str]`, returning the names actually received in a valid response. Add `src/ankiweb_cli/backup_media.py` with `download_all_media(reader: AnkiWebReader, destination: Path, report: Callable[[str], None]) -> list[MediaChange]`. Enumerate from `lastUsn=0` through an empty page, reject non-increasing cursors, interpret empty digests as deletions, download at most 25 names per request, repeat partial ZIP batches until complete, validate `_meta`, SHA-1 and paths, and report each filename. Test >1,000 rows, empty media, unreferenced media, a partial ZIP, stalled pagination, missing/extra/duplicate/traversal ZIP entries, bad hashes, truncated responses and deletion records. Test failure for unsupported legacy names and collisions on the executing filesystem, and preservation of case-distinct files where supported. Run `python -m pytest tests/test_ankiweb_reader.py tests/test_backup_media.py -v` after adding `tests/test_backup_media.py`; verify each new behavior fails before implementation and passes after it.

- [x] **Snapshot verification and package creation.** Create `src/ankiweb_cli/ankiweb_backup.py` and `tests/test_ankiweb_backup.py`. Define `create_verified_package(reader: AnkiWebReader, workspace: Path, report: Callable[[str], None]) -> Path`: record media USN, download the collection, check SQLite integrity, preserve raw `(mod, scm, usn)`, download/verify media, compare `mediaSanity`, recheck media USN and collection metadata, and export a modern package with media from the disposable collection. The caller supplies an isolated temporary workspace inside the output directory, so the package and final name share a filesystem. Validate the archive and its media manifest against the downloaded files and bytes. Implement required checks as errors, never as silent success. Test matching state, each changed value, count mismatch, integrity failure, absent required checks, and an end-to-end synthetic restore containing multiple decks, scheduling/review history and referenced/unreferenced media. Use Anki 24.11 and 26.9.3 as initial test points where installable. Run `python -m pytest tests/test_ankiweb_backup.py -v` before and after implementation; require the latter to pass. Retain the documented uncertainty about undetected server changes and completeness.

- [x] **Publication.** Add `publish_package(package: Path, output_dir: Path) -> Path` to `ankiweb_backup.py` and publication tests to `tests/test_ankiweb_backup.py`. Generate a UTC timestamp and collision suffix; keep the validated temporary package on the output filesystem. Use a tested no-replace operation when available; evaluate the existing `renameat2` and `boltons` candidates before adding dependencies. Where those operations are unsupported, use exclusive final-file creation and copy, with the accepted interruption limitation. Test existing names, competing processes, cleanup failures after successful publication, injected ambiguous publication errors, copy failure/interruption and preservation of all pre-existing files. Resolve ambiguous results before another publication; never silently publish a second completed package. Run `python -m pytest tests/test_ankiweb_backup.py -v` before and after implementation and require the latter to pass. Test and document actual platform behavior rather than extrapolating from ext4.

- [x] **Retries and CLI.** Add `run_backup(output_dir: Path, credentials: BackupCredentials, attempts: int, max_retry_delay: float, report: Callable[[str], None]) -> Path` in `ankiweb_backup.py`; register `ankiweb-backup` in `src/ankiweb_cli/cli.py` and add tests to `tests/test_ankiweb_backup.py` and `tests/test_cli.py`. Require existing `--output-dir` and `--credentials-file`, default to three total attempts and a 60-second cap, enforce attempts >= 1 and cap >= 5, and wait `min(cap, 5 * 2**(retry_number-1))` without real sleeps in tests. Create each fresh isolated temporary workspace inside `output_dir`, clean failed attempts, and avoid re-publication after an ambiguous final operation. Test success after retry, exhaustion, delays/cap, detected changes, workspace placement and cleanup, CLI help/validation, stdout progress, individual names/errors/path, nonzero failures, and secret redaction. Explicitly verify argument-validation errors for the new command are on stdout despite Click's usual stderr behavior. Verify existing `backup list`/`backup restore`, keyring and local sync behavior remain intact. Run `python -m pytest tests/test_ankiweb_backup.py tests/test_cli.py tests/test_backup.py tests/test_sync.py -v` before and after implementation; require the latter to pass.

- [x] **Network restrictions and recovery integration.** Extend `tests/ankiweb_server_fixture.py` and create `tests/test_ankiweb_backup_integration.py`. Use an isolated local Anki server plus an allowlisting proxy; fixture setup may use normal sync only against that local server, never on the backup side. Record all backup-side requests, reject collection uploads, media uploads/deletions and ordinary sync, and test redirects, retries and remote failures. Verify pre-publication failures do not produce a completed backup; test ambiguous publication outcomes separately. Run `python -m pytest tests/test_ankiweb_backup_integration.py -v`; require all tests to pass. If loopback is unavailable in the execution environment, record the restriction and run the tests in CI; do not treat skipped tests as a passed acceptance check.
